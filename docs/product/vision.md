# 产品愿景

## 我们要解决的问题

ClickHouse 的日常工作分散在 SQL 客户端、系统表、监控面板、日志平台和聊天工具中。工程师
经常需要手工拼接上下文：先找到慢查询，再确认节点和副本，复制 SQL 给同事或模型，最后回到
客户端验证。信息在工具之间流失，也很难复现完整的诊断过程。

DataStoria 的目标是成为 **ClickHouse 的智能工作台**：

- 连接到真实数据库后，立即获得 Schema、SQL 和运行状态的统一视图；
- AI 只能在明确连接与权限范围内工作，结论必须附带可验证证据；
- 单节点和集群使用一致的交互，并能明确切换节点、分片、副本或集群汇总；
- 配置、会话、审批和运行状态由服务端保存，浏览器不持有供应商密钥；
- 开发者可在本机轻量运行，团队可用同一安装包平滑部署到生产。

## 产品原则

1. **证据优先**：AI 诊断通过只读工具获取 Schema、系统表和查询结果，不把猜测包装成结论。
2. **安全默认**：密钥只在 Java 服务端加密保存；危险动作需要明确授权；错误信息会脱敏。
3. **数据库原生**：保留 SQL、Explain、系统表和 ClickHouse 概念，不隐藏关键技术细节。
4. **集群可见**：从入口节点发现拓扑，Dashboard 能在集群汇总与指定副本之间切换。
5. **可恢复**：Agent Run、事件、Checkpoint 和待处理动作持久化，断线或重启后可继续。
6. **可部署**：开发与生产统一使用 MySQL 5.7；统一包不依赖 Nginx，同时保留前后端分离能力。

## 目标用户

- ClickHouse 应用开发者：编写、调试和优化 SQL；
- DBA/数据平台工程师：检查集群健康、系统日志和副本状态；
- SRE：快速定位资源、延迟和异常查询问题；
- 团队管理员：管理模型供应商、模型、Agent、Skill 与访问配置。

## 当前边界

DataStoria 管理的是自身配置与工作流，不替代 ClickHouse 的备份、权限系统、资源编排或完整
监控告警平台。AI 工具默认面向诊断与只读分析；生产写入权限应由 ClickHouse 用户和网络策略
共同限制。
